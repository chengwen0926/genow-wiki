# Genow Wiki 轻量化优化方案

## 1. 目标与适用前提

在保留目录导航、Markdown 排版、图片放大、视频播放和章节跳转的前提下，将项目改为可直接部署的静态文档站。

当前内容为仓库中的 5 篇 Markdown，未发现登录鉴权、在线编辑、数据库或动态业务接口。本方案据此假定：内容通过仓库维护，允许修改后重新构建发布。

核心目标：

- 生产环境不再运行 Next.js 和 FastAPI 应用进程，由静态服务器提供页面和媒体。
- 文章正文随 HTML 返回，不依赖浏览器请求 API 后再解析 Markdown。
- 避免不可见视频持续播放，减少不必要的下载、解码和状态更新。
- 降低安装、配置和维护成本，同时补齐文章独立链接和浏览器导航。

本轮不重做视觉设计，不引入搜索、CMS 或数据库。Astro 可作为未来重做界面时的选择，不与本轮迁移同时推进。

## 2. 当前问题与对应措施

| 问题 | 当前证据 | 优化措施 | 主要收益 |
| --- | --- | --- | --- |
| 两套应用服务仅用于展示静态内容 | `backend/main.py` 读取文件、返回目录和正文、挂载媒体 | 构建时读取 Markdown，媒体由静态服务器提供 | 减少运行环境、跨域配置和进程管理 |
| 正文依赖客户端加载 | `frontend/app/page.tsx` 先请求目录，再请求默认文章 | 为每篇文章生成 HTML，首页直接展示默认文章 | 消除正文加载对两次串行 API 请求的依赖 |
| 浏览器解析 Markdown | `WikiContent.tsx` 使用客户端 `react-markdown` | 在构建阶段渲染正文，交互组件单独保留 | 减少客户端解析工作和相关脚本 |
| 文章切换无独立路由 | 页面以 React 状态切换内容 | 使用 `/wiki/<slug>/` 路由和真实导航链接 | 支持分享、刷新、前进后退和深层链接 |
| 视频挂载即自动播放 | `VideoCard` 使用 `autoPlay`、`loop` 并主动调用 `play()` | 默认点击播放，按需挂载资源；不可见时暂停 | 减少无效下载和解码 |
| 遗留图形依赖 | `useShaderBackground` 未被页面引用 | 删除 Hook、`three` 和 `@types/three` | 减少依赖安装和维护成本 |
| 标题目录存在重复实现 | Python 提取标题，前端另行生成 ID | 在同一 Markdown 解析流程中生成标题 ID 和目录 | 避免目录与正文锚点不一致 |

## 3. 推荐架构

保留 Next.js、React、TypeScript 和 Tailwind，使用 Next.js 静态导出。Node.js 只在开发和构建时使用；部署产物仅包含 HTML、CSS、必要 JavaScript 和媒体文件。

```text
content/*.md + assets/
          |
          v
Node.js 构建：读取内容、解析 Markdown、生成目录和页面
          |
          v
frontend/out/：HTML + CSS + JS + media/
          |
          v
静态服务器 / 静态托管平台
          |
          v
浏览器直接读取文章，按需执行媒体交互
```

### 3.1 内容与路由

- 新增仅供构建阶段使用的内容模块，负责递归读取 Markdown、文章排序、标题、目录和更新时间。
- 保留现有文章顺序：控制台模式、画布模式、生成历史、草稿模式、其他。
- 使用静态参数生成全部文章路径，支持未来的嵌套目录；未知路径返回 404。
- 首页在构建时展示默认文章，导航链接指向文章独立路径。
- 不在客户端组件中导入文件系统模块或完整内容集合。
- 页面标题和描述按文章生成；文档语言设置为中文。
- 更新时间优先采用文章显式元数据或 Git 最后修改时间；构建环境取不到时省略，不将重新检出文件的时间冒充内容更新时间。

### 3.2 Markdown 渲染与交互边界

- 将 Markdown 渲染移入服务端组件，在静态构建时执行；`react-markdown`、`remark-gfm` 可继续使用。
- 图片放大和视频播放器保留为小型客户端组件，通过序列化参数接收图片地址、视频地址和说明。
- 导航优先使用真实链接；仅将确实依赖浏览器状态的逻辑放入客户端组件。
- 标题 ID 和目录来自同一份 Markdown AST；处理重复标题、中文、行内代码和格式化文本，避免继续使用正则扫描标题。
- 目录锚点、首次打开带 hash 的文章、前进后退均应可用；正文不依赖 JavaScript 才能出现。
- 将现有 Markdown 中 `.mp4` 链接转播放器的规则迁移到构建渲染阶段，保持现有内容格式兼容。

### 3.3 媒体资源

- 保留 `assets/` 作为源目录，构建前复制到 `frontend/public/media/`，导出后地址仍为 `/media/...`。
- 复制脚本只更新自己管理的媒体输出目录，确保删除源文件后不会遗留旧产物；生成文件不提交到 Git。
- 删除 `NEXT_PUBLIC_API_URL` 拼接，图片和视频统一使用同域路径。
- 默认部署在域名根路径；如需子路径部署，统一处理文章链接和媒体前缀并增加对应验证。
- 页面文件和可变媒体地址使用可重新验证的缓存策略；只有带内容哈希的资源使用长期不可变缓存。

## 4. 实施阶段

### 阶段一：建立基线并清理遗留依赖

1. 记录现有生产构建结果和浏览器数据，区分安装体积、构建体积、实际传输量。
2. 删除未使用的 `useShaderBackground.ts`、`three` 和 `@types/three`，更新锁文件。
3. 检查并清理确认未引用的 CSS；保留现有 Tailwind 和 TypeScript。

验收：页面功能和外观无回归，生产构建成功，安装依赖中不再包含 Three.js。此项不预设首屏传输量会下降，因为未引用的 Hook 通常不进入页面依赖图。

### 阶段二：优化视频与图片加载

1. 移除视频自动播放和挂载时的主动 `play()`，默认由用户点击播放。
2. 使用 `preload="none"`；仅进入视口附近或用户点击时挂载视频资源地址，必要时提供封面。
3. 视频离开可见区域或页面进入后台时暂停；不自动恢复已被用户暂停的视频。
4. 优先使用原生 `controls`；如需保留当前外观，再保留自定义控件，并确保触屏和键盘可操作。
5. 保留图片懒加载，提供宽高或稳定比例；根据实测需求压缩图片、视频或生成封面，避免一开始批量转码。

验收：打开包含 7 个视频的画布模式文章时，不出现 7 个视频同时播放；未交互且远离视口的视频不下载主体内容；播放、暂停、拖动进度和全屏正常。

### 阶段三：迁移静态内容与路由

1. 新增构建期内容模块和静态文章路由，复用现有排序和媒体展示规则。
2. 拆分正文渲染与客户端媒体组件，构建时输出正文和完整目录。
3. 将侧栏按钮改为文章链接，移除客户端目录和文章请求，以及对应加载、错误状态。
4. 添加静态媒体同步脚本，在开发和构建入口执行；开发时增加媒体后也应能同步或明确重新执行入口。
5. 配置 `output: "export"`，结合托管环境配置目录索引，例如使用 `trailingSlash: true`。
6. 验证导出产物在没有 FastAPI、没有 Next.js 运行进程时能够独立服务。

验收：直接访问、刷新全部文章路径成功；页面 HTML 包含正文；导航、锚点、404 和媒体正常；浏览器不再请求 `/api/wiki/*` 或后端 8002 端口。

注意：只配置 `output: "export"` 不足以取消后端，必须同时迁移内容读取、正文渲染和资源路径。

### 阶段四：收敛部署与发布流程

1. 静态产物验收通过后，移除 `backend/`、旧 `frontend/lib/api.ts` 和前后端环境变量配置。
2. 移除或替换当前 `setup.py` 双进程启动流程，统一为 Node.js 安装、开发、构建命令。
3. 更新 README，明确内容编辑、媒体同步、构建、静态托管、缓存策略和回滚方式。
4. 确保媒体与页面属于同一发布版本；发布时保留上一版产物，便于整体回滚。
5. 若接入 CI，提交内容后自动构建并发布，弥补取消运行时读取后的更新流程变化。

验收：干净环境按 README 能完成构建；生产环境无需 Python 或 Node.js 应用进程；更新文章后可发布并回滚至上一版本。

## 5. 验证与效果评估

统一使用生产构建、同一设备与浏览器、相同网络限制进行前后对比。分别记录默认文章和视频较多的画布文章，区分首次打开与再次访问。

| 维度 | 记录或验证内容 | 目标 |
| --- | --- | --- |
| 部署 | 应用进程与运行环境 | 两套应用服务变为静态托管 |
| 内容可用性 | 检查页面源 HTML，禁用 JavaScript 阅读正文 | 正文和基础导航仍可用 |
| 网络请求 | API 调用、首屏 JS/CSS、媒体请求与传输量 | 无 Wiki API 请求，减少不必要资源加载 |
| 加载体验 | FCP、LCP、CLS，重复采样记录中位数 | 较基线改善或无明显退化 |
| 视频资源 | 同时播放数量、隐藏标签页与滚出视口后的状态 | 只播放用户需要的视频 |
| 导航 | 独立链接、刷新、前进后退、中文与重复标题锚点 | 均正常 |
| 内容兼容 | 5 篇文章、全部图片视频、列表和 GFM 表格 | 无内容和交互丢失 |
| 响应式 | 桌面及手机视口、触屏与键盘操作 | 无遮挡、溢出或不可达控件 |

自动化检查聚焦内容模块的排序、嵌套 slug、重复标题和缺失资源，以及静态路由冒烟验证；不为简单依赖删除单独编写测试。

当前观测的本地占用约为：`node_modules` 419 MB、`.next` 246 MB、媒体 30 MB、正文目录 24 KB、Three.js 及其类型包合计 43 MB。这些是磁盘占用，不是浏览器传输量；尚未进行性能实测，不承诺固定比例的速度或内存改善。

## 6. 关键取舍与完成标准

- **内容更新方式改变：** 从运行时读取服务器文件，改为编辑后构建发布。如果必须保留“不构建立即生效”，需改评估单一服务架构，而不是直接执行本方案。
- **视频默认行为改变：** 从自动循环播放改为点击播放，降低阅读时的资源消耗；确需自动演示时，再增加受可见性控制的播放模式。
- **仍保留 React 与 Next.js 的客户端基础开销：** 静态导出不等于零 JavaScript，但可复用现有组件、控制迁移成本。若实测仍不满足目标，再评估 Astro。
- **功能完整性优先：** 不因取消后端而牺牲媒体播放、完整目录、中文路径或文章独立访问。

完成标准：所有现有文章及媒体正常展示，正文由构建生成，生产无需应用服务，无 Wiki API 依赖，视频按需加载，发布和回滚流程可复现。
